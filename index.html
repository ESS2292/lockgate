What it checks

  • lockgate check — primary command
  • Mixed package-manager lockfiles in the same directory (npm shrinkwrap plus package-lock.json is valid, not mixed)
  • A missing lockfile, or one listed in .gitignore / .dockerignore. If the lockfile is gitignored, that is treated as a library policy: a warning, not a failure
  • A Corepack packageManager field that does not match the lockfile in scope
  • npm package-lock.json / npm-shrinkwrap.json compared to direct dependencies
  • GitHub Actions run: steps that invoke npm install instead of npm ci, or Yarn / bun without a frozen flag
  • Dockerfiles that RUN npm install or copy package.json without the lockfile
  • --json, --ignore, --root, --allow-mixed, --lockfile-policy, --include-fixtures
  • Exit codes: 0 pass, 1 violations, 2 usage or missing root

What it is not

  • Not a reimplementation of npm's arborist or a full npm ci ideal-tree check
  • Yarn, pnpm, and bun lockfiles are detected, not fully parsed for manifest sync in 0.1.0
  • Not a full YAML or Dockerfile parser
  • Does not call the network or install packages
  • Lite (the GitHub Action) does not check npm sync or Dockerfiles. It does read .gitignore to detect a library lockfile policy

Lite vs the full CLI

LockGate Lite is a free GitHub Action that checks mixed or missing lockfiles, packageManager mismatches, and unfrozen CI installs. Use it as ESS2292/lockgate-action@v1. If a lockfile name is gitignored, Lite treats that as a common library policy: it warns instead of failing, and does not flag npm install in CI (a library that does not commit a lockfile cannot run npm ci). Manifests under tests/fixtures-style paths are skipped by default. The $19 CLI adds npm manifest-vs-lockfile sync, Dockerfile COPY / RUN checks, a JSON report, and a command you can run on a laptop or in any CI. Checkout is not live.

CI sketch

From the bundled workflow sketch. Prefer npm ci (or the equivalent frozen install for Yarn, pnpm, or bun) so CI cannot rewrite the lockfile.

.github/workflows/lockgate-example.yml 
# Example only — copy into a consuming repository. The paid CLI is not published yet.
name: LockGate

on:
  pull_request:
  push:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Install LockGate
        run: npm install -g .

      - name: Check lockfiles and install commands
        run: lockgate check

Honest limits

  • npm comparison is direct dependencies only. peerDependencies are not required to appear as installed lockfile entries.
  • Yarn, pnpm, and bun lockfiles are detected and checked for mixed, missing, and install-command issues; their bytes are not fully parsed for sync in 0.1.0. Use the official frozen install as the sync check for those managers.
  • Workflow and Dockerfile parsing is best-effort, not a complete YAML or Dockerfile implementation. ARG / --from / heredoc RUN are not fully expanded.
  • pnpm's default --frozen-lockfile in CI is respected: a bare pnpm install in GitHub Actions is a warning, because GitHub sets CI=true. Docker is not assumed to be CI.
  • Bare yarn install is a warning when the repo's yarn.lock is Yarn Berry (immutable on CI by default) and an error on Yarn 1, which does not have that default.
  • A gitignored lockfile is treated as an intentional library policy by default (lockfile-policy: auto). Warnings stay visible and do not fail the check. Set lockfile-policy: app (or --lockfile-policy app on the CLI) if the ignore was a mistake, or library to force the policy without a gitignore.

FAQ

Is this the same as EnvGate or RuntimeGate?

No. EnvGate checks environment files for missing keys, placeholders, and a narrow set of secret shapes. RuntimeGate checks whether runtime version pins agree. LockGate checks whether the dependency install is frozen and repeatable. They share an audience (CI and DevOps) and the same “fail the job, not the deploy” idea. The free EnvGate Lite and RuntimeGate Lite Actions are published separately.

Why $19 if the source is MIT?

MIT allows selling copies. The price is for a packaged, tested release with docs and a CI sketch, not exclusive ownership of the code. Buyers (and others) may redistribute under MIT terms.

What about libraries that gitignore their lockfiles?

That is treated as an intentional policy. Libraries such as ESLint and Express gitignore package-lock.json (and often yarn.lock) because consumers resolve their own tree. Lite and the CLI then report a missing lockfile as a warning, not a failure, and they do not flag npm install in CI. You can force the same policy with lockfile-policy: library, or keep strict app rules with lockfile-policy: app. Manifests under tests/fixtures-style paths are skipped by default.

Does Lite check npm sync or Dockerfiles?

No. LockGate Lite checks mixed or missing lockfiles, packageManager mismatches, and unfrozen CI installs only. It reads .gitignore only to detect a library lockfile policy. npm manifest-vs-lockfile sync and Dockerfile COPY / RUN checks are in the full CLI. Checkout is not live.

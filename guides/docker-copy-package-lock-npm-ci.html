Copy the lockfile and run npm ci in Docker

COPY package.json . followed by RUN npm install builds an image from ranges, not from the committed lockfile. The official Node.js Docker examples do not do that.

A Dockerfile that copies only package.json cannot run a frozen install: npm ci requires the lockfile, and npm install without it will resolve a new tree and, if the lockfile later appears, may rewrite it. Listing the lockfile in .dockerignore has the same effect, even when you write COPY . . or COPY package*.json ./.

The Stack Overflow thread Should I copy package-lock.json to the container image in Dockerfile? has a score of 22 and 18,294 views (Stack Exchange API, 10 November 2026). The accepted answer (score 38) says to copy the lockfile and use npm ci.

That is also what the official image documentation recommends. The Node.js Docker official-image BestPractices.md (fetched 10 November 2026) uses this pattern in both the Alpine and Debian examples:

COPY package*.json ./
RUN npm ci

The package*.json glob copies both package.json and package-lock.json. After the install, you can copy the rest of the application. The install layer then only invalidates when the manifest or the lockfile changes.

Do not rely on CI defaults inside an image

pnpm and Yarn Berry freeze by default when CI=true. GitHub Actions sets that variable; a Docker build often does not. A bare pnpm install or yarn install in a RUN line can therefore rewrite the lockfile during the image build even if the same command would freeze in CI. Prefer an explicit flag: npm ci, pnpm install --frozen-lockfile, yarn install --immutable (or --frozen-lockfile on Yarn 1), or bun ci.

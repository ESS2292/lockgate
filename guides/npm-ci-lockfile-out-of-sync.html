Why npm ci fails when the lockfile is out of sync

npm ci is supposed to be the frozen install. It still fails, often as the first step of CI, when someone edited package.json and did not regenerate package-lock.json.

Official npm documentation for npm ci is unambiguous: the command requires a lockfile, exits with an error when the lock and package.json do not match, and never rewrites either file — unlike npm install. See the npm-ci docs (npm 11.21.2, fetched 10 November 2026).

That official error string is still showing up in open tickets. StellarCommons/Stellar-Explain #1514 (opened 10 November 2026) reports UI and publish jobs failing with npm ci can only install packages when package.json and package-lock.json are in sync. Missing: @testing-library/react@16.3.3 from lock file — 15 missing entries, reproduced locally with npm ci --dry-run. AbhinavDasari-pennstate/revampDesign #20 (7 November 2026) is the same EUSAGE failure on a clean Ubuntu runner, before any tests run.

A GitHub issue and pull-request search for the exact phrase "can only install packages when your package.json and package-lock.json" returned 4,158 results on 10 November 2026. That is a search hit count, not a count of unique bugs, but it is evidence the error is recurrent. On Stack Overflow, threads about the same failure include a DigitalOcean app deploy (score 6, 10,751 views) and a Heroku deploy (score 1, 6,517 views). View and score counts are from the Stack Exchange API on 10 November 2026.

Catch it before the install deletes node_modules

npm ci is the check, but it is a heavy one: it deletes node_modules and installs from the lockfile. A Stack Overflow question specifically asks for a faster parity check (score 7, 6,298 views). A 2022 answer recommends npm ci --dry-run --ignore-scripts for that job.

A CI gate that compares direct dependencies in package.json to the lockfile can fail earlier, with a shorter message, without installing anything. That is what the LockGate CLI does for npm lockfiles. It is not a reimplementation of npm's arborist, and it does not replace npm ci as the install.

The free LockGate Lite Action does not include this npm sync check. Lite looks at mixed or missing lockfiles and at whether CI ran npm install instead of npm ci. If CI already uses npm ci, Lite will not tell you the lockfile is stale — npm ci itself will. The full CLI adds the earlier sync check, plus Dockerfile inspection. Checkout is not live.
